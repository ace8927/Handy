# Handy — Windows + Remote STT

Эта модификация исходников Handy содержит **только** переключатель источника распознавания речи. Локальный движок и вся существующая обработка текста, hotkeys, VAD, история, оверлей и LLM post-processing сохраняются.

## Что добавлено

**Настройки → Advanced → Transcription → STT engine**:

- **Local** — оригинальный Handy без изменений в локальном STT-пайплайне.
- **Remote STT** — аудио отправляется на OpenAI-совместимый сервер.
- **Server URL** — `http://192.168.1.20:8000/v1`, адрес должен быть доступен с Windows-ПК.
- **Model** — точный ID модели на уже работающем STT-сервере, например `whisper-1` (название по умолчанию является примером, его может потребоваться заменить).
- **API Key** — необязательный токен; если введён, используется `Authorization: Bearer <ключ>``
- **Save STT settings** — сохраняет конфигурацию и применяет выбранный режим. Если включить Remote, локальный ASR выгружается.

В Remote-режиме отправляется `POST /v1/audio/transcriptions` с multipart WAV 16 kHz mono 16-bit PCM, полями `file`, `model`, `response_format=json` и необязательным `language`. Ожидается `{"text":"..."}`. Результат попадает в существующую обработку текста и LLM Handy. Ни отдельного сервера, ни новых моделей, ни streaming/fallback-функций не добавлено.

> Локальная модель Handy **не загружается** в Remote-режиме, но сам легковесный захват аудио и локальный VAD по-прежнему работают. Доступ к серверу должен быть защищён: незашифрованный `http://` рекомендуется только внутри доверенной LAN/VPN; для доступа через интернет нужен HTTPS.

## Как получить Windows `.exe`

### Вариант A: GitHub Actions (проще при наличии репозитория)

1. Загрузить содержимое этого архива **в свой GitHub-репозиторий**, сохранив скрытую папку `.github`. Для экономии CI-минут отключить ненужные оригинальные workflows с автоматическим запуском по `push` (`Main Branch Build` и др.); наш новый workflow запускается вручную.
2. Открыть **Actions → Windows Remote STT EXE → Run workflow**.
3. После успешного выполнения открыть артефакт **handy-remote-stt-x86_64-pc-windows-msvc**.
4. В нём находится Windows installer `*.exe` (NSIS), а также MSI (если workflow соберёт все исходные типы пакетов). Это **неподписанная пользовательская сборка**.

Workflow переиспользует Windows pipeline официального Handy, включая установку Vulkan SDK, SPIRV-Headers и упаковку VC++ runtime. Подпись официального разработчика отключена. Артефакт появляется **только после успешной сборки в GitHub Actions**; сам по себе этот архив — исходный код, не готовый EXE.

### Вариант Б: локальная сборка на Windows x64

Необходимы **Visual Studio C++ Build Tools**, **Rust stable (`cargo`)**, **Bun**, **CMake**, **Vulkan SDK** и **vcpkg/SPIRV-Headers**. Установка и требования описаны в оригинальном `BUILD.md`.

В PowerShell из каталога проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-windows-remote-stt.ps1
```

Скрипт проверяет зависимости, готовит runtime DLL, временно удаляет недоступную сторонним разработчикам подпись Azure, собирает NSIS и восстанавливает оригинальный `tauri.conf.json`. При успехе установщик ожидается в:

```text
src-tauri\target\release\bundle\nsis\*.exe
```

## Важно

- Это **исходный патч**, а не протестированный на Windows исполняемый файл. Перед эксплуатацией требуется реальная сборка и проверка на Windows с вашим STT-сервером.
- **Windows-подпись разработчика Handy недоступна**: Windows SmartScreen может предупреждать о неизвестном издателе.
- Установщик использует исходный идентификатор приложения Handy: перед установкой рекомендуется сохранить копию настроек/истории. Не ставьте его поверх работающего Handy.
- Для неподписанного установщика в сборочной конфигурации отключён канал обновления оригинального Handy, чтобы официальное обновление не перезаписало модификацию.
- Выбор Local/Remote относится именно к STT, а не к LLM post-processing.
- Для режима Remote ошибки соединения показываются как ошибки транскрибации; локального fallback нет, поскольку он не запрашивался.
